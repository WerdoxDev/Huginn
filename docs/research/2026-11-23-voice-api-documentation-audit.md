# Voice API documentation audit

Researched 2026-11-23 against repository source. This is an audit of the documented SDK and its server contracts, not a proposal to change runtime behavior. No tests were run or modified. Sources are local primary sources; line references describe the inspected working tree.

## SDK documentation mismatches

### Default voice URL is out of date, and custom deployment setup omits the HTTP API

The configuration page lists `wss://midgard.huginn.dev/voice-gateway` as the default and uses `/voice-gateway` in its custom deployment example ([configuration.md:33](../../packages/huginn-docs/api/reference/configuration.md#L33), [configuration.md:137](../../packages/huginn-docs/api/reference/configuration.md#L137)). The SDK defaults are now `wss://midgard.huginn.dev/voice` for signaling and `https://midgard.huginn.dev/voice` for HTTP ([utils.ts:35](../../packages/huginn-api/src/utils.ts#L35)). The deployed reverse proxy can choose a custom WebSocket path, but the documented default does not match the code.

The documented `VoiceOptions` omits `api` and `transportOptions` ([configuration.md:95](../../packages/huginn-docs/api/reference/configuration.md#L95)). Actual options include both, with transport settings `deviceOptions`, `iceTransportPolicy`, and the declared required `voiceApi` field ([types.ts:33](../../packages/huginn-api/src/types.ts#L33)). The current implementation constructs the ICE endpoint from **top-level `voice.api`**, not `transportOptions.voiceApi` ([voice.ts:38](../../packages/huginn-api/src/voice.ts#L38), [voice-transport-manager.ts:112](../../packages/huginn-api/src/voice-transport-manager.ts#L112)). Following the documented custom deployment example therefore leaves ICE credential requests targeting the default instance. Document `voice.api` alongside the WebSocket URL, and accurately distinguish the declared nested field from the option the implementation actually reads.

### TURN and forced-relay setup and errors are missing

The SDK fetches `${voice.api}/ice-servers` with the client's access token, using global `fetch`, a ten-second timeout, and a default ICE transport policy of `all`. Under `all`, credential fetch failures allow transport creation to continue without those servers; under `relay`, failures throw `TransportError` with `RELAY_CREDENTIALS_UNAVAILABLE`, and a response without TURN URLs throws `RELAY_NOT_CONFIGURED` ([voice-transport-manager.ts:116](../../packages/huginn-api/src/voice-transport-manager.ts#L116), [voice-transport-manager.ts:328](../../packages/huginn-api/src/voice-transport-manager.ts#L328), [constants.ts:87](../../packages/huginn-shared/src/constants.ts#L87), [errors.ts:129](../../packages/huginn-shared/src/errors.ts#L129)). These behaviors and configuration controls are absent from the configuration and recovery sections ([configuration.md:92](../../packages/huginn-docs/api/reference/configuration.md#L92), [guide/voice.md:175](../../packages/huginn-docs/api/guide/voice.md#L175)). Also, the reference declares `TransportError.code` optional, while the implemented property and constructor argument are required ([configuration.md:176](../../packages/huginn-docs/api/reference/configuration.md#L176), [types.ts:62](../../packages/huginn-api/src/types.ts#L62)).

### Stored voice state and event payload are incomplete

The stored-state example omits `isCameraInverted` and the `userId`, `sessionId`, `channelId`, and `guildId` fields ([reference/voice.md:53](../../packages/huginn-docs/api/reference/voice.md#L53)). All are present in the public state ([voice-state.ts:23](../../packages/huginn-api/src/voice-state.ts#L23)). The `gateway_voice_state_updated` event is documented as `GatewayVoiceStateFlags`, but its actual payload is the full `GatewayVoiceState`, including connection identity ([reference/voice.md:81](../../packages/huginn-docs/api/reference/voice.md#L81), [voice-state.ts:17](../../packages/huginn-api/src/voice-state.ts#L17)).

### State confirmation and reset do not always restore defaults

The reference describes `confirmGatewayVoiceState()` as replacing flags with the server-confirmed value ([reference/voice.md:73](../../packages/huginn-docs/api/reference/voice.md#L73)). When the confirmed `channelId` is null, the implementation preserves locally selected media flags, including mute, deafen, and camera inversion ([voice-state.ts:83](../../packages/huginn-api/src/voice-state.ts#L83)). The guide also says session/hard reset returns media state to defaults ([guide/voice.md:177](../../packages/huginn-docs/api/guide/voice.md#L177)). Those resets clear transports and explicitly clear only camera-on, screen sharing, and audio-streaming flags; mute, deafen, camera inversion, local pause, and preferences are retained ([voice.ts:81](../../packages/huginn-api/src/voice.ts#L81), [voice-manager.ts:140](../../packages/huginn-api/src/voice-manager.ts#L140), [voice-transport-manager.ts:788](../../packages/huginn-api/src/voice-transport-manager.ts#L788)).

### Event list omits connection failures and advertises an event that is never emitted

`Voice` exposes `connection_error: Error`, emitted when signaling-ready device/transport setup fails; `connectVoice()` listens to it and rejects ([voice.ts:12](../../packages/huginn-api/src/voice.ts#L12), [voice.ts:89](../../packages/huginn-api/src/voice.ts#L89), [voice-manager.ts:193](../../packages/huginn-api/src/voice-manager.ts#L193)). The voice event table omits it ([reference/voice.md:24](../../packages/huginn-docs/api/reference/voice.md#L24)). Conversely, the transport event table lists `transport_disconnected`, but the implementation only declares that event type and never emits it; transport failures update `status_changed` ([reference/voice.md:224](../../packages/huginn-docs/api/reference/voice.md#L224), [voice-transport-manager.ts:84](../../packages/huginn-api/src/voice-transport-manager.ts#L84), [voice-transport-manager.ts:138](../../packages/huginn-api/src/voice-transport-manager.ts#L138), [voice-transport-manager.ts:160](../../packages/huginn-api/src/voice-transport-manager.ts#L160)).

### Connection and low-level method descriptions miss observable behavior

- The guide says `connectVoice()` waits for a fresh token. The implementation can reuse a cached token younger than ten minutes, or accept the supplied token; it still waits for the gateway state request to finish. The token/state acquisition phase has a 15-second deadline and is cancelled by disconnect. This is not a timeout for the entire call connection ([guide/voice.md:26](../../packages/huginn-docs/api/guide/voice.md#L26), [voice-manager.ts:150](../../packages/huginn-api/src/voice-manager.ts#L150), [voice-manager.ts:258](../../packages/huginn-api/src/voice-manager.ts#L258), [voice-manager.ts:275](../../packages/huginn-api/src/voice-manager.ts#L275), [constants.ts:15](../../packages/huginn-shared/src/constants.ts#L15), [constants.ts:86](../../packages/huginn-shared/src/constants.ts#L86)).
- `checkStatus()` requires signaling status `authenticated` or `resuming` as well as connection data, while the reference mentions only connection data ([reference/voice.md:251](../../packages/huginn-docs/api/reference/voice.md#L251), [voice-signaling-client.ts:454](../../packages/huginn-api/src/voice-signaling-client.ts#L454)).
- Public `VoiceState.resendGatewayVoiceState(): Promise<void>` is absent from the methods table ([reference/voice.md:68](../../packages/huginn-docs/api/reference/voice.md#L68), [voice-state.ts:73](../../packages/huginn-api/src/voice-state.ts#L73)).

## Wire and server findings

### Material omission: voice has a separate authenticated HTTP endpoint for ICE servers

The voice guide describes signaling and mediasoup transports but does not describe the HTTP prerequisite for TURN credentials ([guide/voice.md:8](../../packages/huginn-docs/api/guide/voice.md#L8), [reference/voice.md:160](../../packages/huginn-docs/api/reference/voice.md#L160)). The voice service mounts both WebSocket `/voice` and an HTTP route ([huginn-voice/src/index.ts:23](../../packages/huginn-voice/src/index.ts#L23)). `GET /voice/ice-servers` uses `verifyJwt()`, returns `{ iceServers: [] }` when Cloudflare TURN is unconfigured, otherwise requests credentials with a one-day TTL and returns the provider's validated response. Provider HTTP failures and invalid responses return 500 ([routes/ice-servers.get.ts:8](../../packages/huginn-voice/src/routes/ice-servers.get.ts#L8)). This endpoint belongs in the voice setup/configuration explanation because custom deployments need a reachable HTTP voice API as well as a WebSocket URL; SDK configuration implications are covered below.

### Material omission: gateway voice-token delivery is conditional and scoped to the requesting session

The gateway guide lists `voice_server_update` only by name ([guide/gateway-events.md:79](../../packages/huginn-docs/api/guide/gateway-events.md#L79)). Its entire payload is `{ token: string }`; it does not contain a voice endpoint ([gateway-types.ts:239](../../packages/huginn-shared/src/gateway-types.ts#L239)). The server issues it to the requesting gateway session when joining a different channel, changing gateway session, or updating state after the cached token expiry; ordinary flag updates in the same channel do not necessarily issue a new token ([server-gateway.ts:364](../../packages/huginn-server/src/gateway/server-gateway.ts#L364)). Tokens last ten minutes ([constants.ts:14](../../packages/huginn-shared/src/constants.ts#L14)). A concise gateway event payload/lifecycle explanation would make token acquisition and endpoint discovery understandable without reading the source.

### Material omission: only one voice-signaling session is retained per user

The documented connection methods do not mention the effect of identifying from another client ([reference/voice.md:44](../../packages/huginn-docs/api/reference/voice.md#L44), [reference/voice.md:247](../../packages/huginn-docs/api/reference/voice.md#L247)). On voice identify, the server finds an existing authenticated session for the user, closes it with `INTENTIONAL_CLOSE`, and deletes that session before initializing the new one ([voice-websocket.ts:915](../../packages/huginn-voice/src/voice-websocket.ts#L915)). Deletion closes that session's transports and producers, removes its peer, and broadcasts `peer_left` ([voice-websocket.ts:82](../../packages/huginn-voice/src/voice-websocket.ts#L82)). The main gateway likewise records one voice state per user and sends a null state to the previous gateway session on takeover ([gateway/voice-manager.ts:139](../../packages/huginn-server/src/gateway/voice-manager.ts#L139), [gateway/voice-manager.ts:178](../../packages/huginn-server/src/gateway/voice-manager.ts#L178)). This is observable multi-client call behavior, not just an implementation detail.

### Material omission: voice resume has server retention and replay limits

The guide says signaling can resume after interruptions without describing the bounds ([guide/voice.md:177](../../packages/huginn-docs/api/guide/voice.md#L177)). The voice service configures a 60-second stale-session retention period and a 20-message replay buffer ([voice-websocket.ts:39](../../packages/huginn-voice/src/voice-websocket.ts#L39), [constants.ts:26](../../packages/huginn-shared/src/constants.ts#L26)). Common session handling immediately deletes authenticated sessions on `INVALID_SESSION`, `INTENTIONAL_CLOSE`, or `GOING_AWAY`; other authenticated closes mark the session stale and schedule deletion ([common-websocket.ts:79](../../packages/huginn-backend-shared/src/websocket/common-websocket.ts#L79), [common-websocket.ts:178](../../packages/huginn-backend-shared/src/websocket/common-websocket.ts#L178)). Resume requires an existing authenticated session for the same user, rejects invalid/future sequence values or insufficient replay history, and replays retained messages after the supplied sequence ([common-websocket.ts:233](../../packages/huginn-backend-shared/src/websocket/common-websocket.ts#L233), [common-websocket.ts:280](../../packages/huginn-backend-shared/src/websocket/common-websocket.ts#L280)). Voice resume separately verifies the voice token ([voice-websocket.ts:988](../../packages/huginn-voice/src/voice-websocket.ts#L988)). Document these as recovery limits; do not promise every interruption is resumable.

### Optional documentation expansion: no dedicated voice wire-protocol reference

The current voice reference is explicitly an SDK class/method reference; its signaling section lists SDK requests and points to `VoiceWebsocketEvents` ([reference/voice.md:254](../../packages/huginn-docs/api/reference/voice.md#L254)). That is not itself an inaccuracy. Clients implementing signaling without the SDK would need a separate protocol reference covering:

- Opcodes `HELLO=0`, `IDENTIFY=1`, `HEARTBEAT=2`, `HEARTBEAT_ACK=3`, `DISPATCH=4`, and `RESUME=7`; dispatch envelope `{ op, s?, t, d }` ([voice-types.ts:6](../../packages/huginn-shared/src/voice-types.ts#L6), [voice-types.ts:97](../../packages/huginn-shared/src/voice-types.ts#L97)).
- Hello `{ heartbeatInterval, sessionId }`, identify `{ token, channelId, guildId }`, ready `{ rtpCapabilities, producers, consumers }`, and resume `{ token, sessionId, seq }` ([voice-types.ts:142](../../packages/huginn-shared/src/voice-types.ts#L142)). Server hello and heartbeat ACK are emitted by [voice-websocket.ts:48](../../packages/huginn-voice/src/voice-websocket.ts#L48) and [voice-websocket.ts:1013](../../packages/huginn-voice/src/voice-websocket.ts#L1013).
- Request/result dispatch names, optional nonce correlation, and result unions with `{ error: number, nonce? }` ([voice-types.ts:39](../../packages/huginn-shared/src/voice-types.ts#L39), [voice-types.ts:110](../../packages/huginn-shared/src/voice-types.ts#L110), [voice-types.ts:175](../../packages/huginn-shared/src/voice-types.ts#L175)). Numeric signaling errors are declared separately from WebSocket close codes ([errors.ts:90](../../packages/huginn-shared/src/errors.ts#L90), [errors.ts:118](../../packages/huginn-shared/src/errors.ts#L118)).
- Separate send/receive transport directions; producing on a receive transport and consuming on a send transport return `WRONG_TRANSPORT_DIRECTION` ([voice-websocket.ts:354](../../packages/huginn-voice/src/voice-websocket.ts#L354), [voice-websocket.ts:498](../../packages/huginn-voice/src/voice-websocket.ts#L498)). New server consumers are paused and need a subsequent `resume_consumer` ([voice-websocket.ts:387](../../packages/huginn-voice/src/voice-websocket.ts#L387), [voice-websocket.ts:193](../../packages/huginn-voice/src/voice-websocket.ts#L193)).

## Related backend/documentation mismatch: selected ringing recipients are ignored

The REST reference promises `ring(channelId, recipients)` rings selected recipients, or all recipients for `null` ([reference/rest-apis.md:84](../../packages/huginn-docs/api/reference/rest-apis.md#L84)). The SDK sends the supplied list unchanged ([rest-apis/channel.ts:164](../../packages/huginn-api/src/rest-apis/channel.ts#L164)). The server validates a supplied list against channel recipients, but then calls `addCall()` with **every other channel recipient**, regardless of the validated list ([call/ring.post.ts:14](../../packages/huginn-server/src/routes/channels/%5BchannelId%5D/call/ring.post.ts#L14), [call/ring.post.ts:25](../../packages/huginn-server/src/routes/channels/%5BchannelId%5D/call/ring.post.ts#L25), [call/ring.post.ts:36](../../packages/huginn-server/src/routes/channels/%5BchannelId%5D/call/ring.post.ts#L36)). An existing call returns 204 without changing ringing ([call/ring.post.ts:29](../../packages/huginn-server/src/routes/channels/%5BchannelId%5D/call/ring.post.ts#L29)). This is confirmed runtime divergence and needs a product decision about whether to fix the server or describe its current behavior; changing only the SDK signature would not resolve it.
